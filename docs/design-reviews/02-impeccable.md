## (a) Lens summary — what *impeccable* demands

The skill demands finished work, verified by **looking at the rendered result at the sizes it ships at** — not at intentions. Mode matters: this console is **Operate** ("the visitor completes a task"), where ambition shows as *precision and restraint* — scanability, consistency, and brand living "in precise details." The `craft-floor` reference sets the rubric: a **Verify** list (contrast ≥4.5:1 body / ≥3:1 large; shadows carry offset *and* blur; spacing on a strict grid with more space above a heading than below; type that survives every breakpoint; one authored motion moment with exponential ease-out; all control states present; browser surfaces themed; copy that names the problem *and* the recovery) and a **Refuse** list of category defaults (gradient text, colored border-left above 1px, hard offset shadows, unicode glyphs standing in for an icon system, monospace as costume…), of which exactly one is an absolute **ban**: the kicker/eyebrow above a heading. Its sharpest line: *text selection, caret, scrollbars, focus rings and tabular numerals "all ship with browser defaults that belong to no design system … This is the cheapest signal that a page was built rather than assembled, and the one models skip most reliably."* Polish is refinement, never concealed redesign; fix causes at the narrowest correct level; batch checks; never perfect one corner while the rest sits below the same bar.

## (b) Verdict + score

**7/10.** This is an unusually *built* console — a three-tier token system with a WebGL bridge so cards and map can never disagree, a documented motion grammar, enforced red discipline, and copy that names problem and recovery — but it is *done*, not yet *impeccable*: at its own verified 1280×800 floor viewport the current e2e capture shows topbar cells rendered on top of each other, the primary chart's axis labels are amputated mid-glyph at two reference sizes, and the two "browser surfaces" the skill calls the cheapest polish signal (selection, caret) are unthemed.

## (c) Findings (P0/P1/P2)

There are no P0s: nothing found blocks task completion, and the 10-30 fix commit `a8c91f7` ("plan-card options no longer clip at laptop viewports") already cleared the worst card-clipping case — confirmed in the current capture where "Authorize P-1 / Reject plan" render fully above the dock (qa/e2e-break-1280.png).

### P1-1 · Topbar cells render superimposed at the console's own 1280×800 floor viewport
**Evidence.** `qa/e2e-break-1280.png` (crop of region 140,8–660,62 at 3×): the situation title ("Encina…"), the posture pill's red dot and "PLAN", and the gate chip "GATE 10:00 LEFT" are painted **on top of one another** into illegible glyph soup, with the TFR chip (`TFR · AIR ATTACK OPS · UAS FLOOR < 150'` — copy itself is correct, feet-prime) beside them. The same cells render cleanly at 1920 in `qa/calm-plan.png` (same crop region) — so this is a width-driven break, not a content bug. Dating: `ls -la --time-style=long-iso qa/e2e-break-1280.png` → **2026-10-30 21:11**, the same minute as HEAD commit `798ae1b` (git log) — this is the *current* render, produced by the e2e battery shot `'break-1280'` (`tools/e2e.mjs:288`, `open('situation=wui-breakout&phase=D', 1280, 800)` at :282). The V1 check at `tools/e2e.mjs:289` asserts page overflow, rail, cards and widgets — **nothing asserts topbar-cell collision**. The compact rule (`console.css:997-1000`, `@media (max-width: 1310px)`) hides `.sitbtn small` but does not constrain the title + posture + gatechip + TFR-chip row (the TFR chip is rendered by `commandConsole.ts:535`).
**Why it matters.** The anatomy's note 4 (`docs/anatomy/index.html`: "Reference viewport 1280 × 800 (verified floor)") makes 1280 the contract viewport; there, the operator's primary context line — which incident, which posture, how long the gate stays open — is unreadable. Craft-floor Verify: "Run the real copy at every breakpoint and fix what overflows."
**Fix (buildable).** In the ≤1310px media block: `flex: none` on `.posture`, `.gatechip` and the TFR chip; cap the situation button (`flex: 0 1 auto; max-width: 34ch` — the inner `b`/`small` already ellipsize, `console.css:430-431`); drop the TFR chip into the hidden `.kpi.opt` budget at ≤1310px (it already has a title tooltip). Then add to V1 (`tools/e2e.mjs:289`): assert that no two of `topbar`'s children bounding boxes intersect at 1280×800 with `situation=wui-breakout&phase=D` — the exact state this capture shows.

### P1-2 · Fire growth chart's x-axis tick labels are amputated mid-glyph and overlap each other
**Evidence.** `qa/final-polish.png` (crop 328,680–745,900 at 2×): the tick row under the burned-area chart is cut by the widget's bottom edge — the bottom ~40% of every glyph is missing — and adjacent labels collide ("+30 m" printed over "T+1:1…"); the "T+0:01" first label is cut to "5+0:01". Also visible at 1280 in the **current** `qa/e2e-break-1280.png` (crop 990,565–1280,800), so the defect survives the 10-30 fix passes. Cause in source: `.chart { … overflow: visible }` (`console.css:858`) lets the SVG axis text (`.chart .axis`, `--fs-chart` 10.5px, `console.css:860`) paint below the SVG box; `.wbody` gives only 12px bottom padding (`console.css:796`), and `.widget { overflow: hidden }` (`console.css:751`) amputates whatever crosses. The scroll-fade mask that should soften a clipped bottom (`.fade-y, .wbody, …`, `console.css:935-940`) shows no fade at the cut in either capture — the labels hard-clip instead.
**Why it matters.** The time axis is the only way to read *when* the projection lands ("T+1:30", "T+3:00") — a fire-growth projection without a legible time axis is decoration next to a number.
**Fix (buildable).** Reserve the label band inside the chart geometry: lift the tick baseline ~14px above the SVG's bottom edge (or grow the viewBox height by the `--fs-chart` line and move `axis` text up), so `overflow: visible` is never relied upon; alternatively `padding-bottom: 18px` on the growth widget's `.wbody`. Add an e2e assertion that no `.chart .axis` text bbox crosses its `.wbody` clip rect at 1280×800 and 1440×900.

### P1-3 · Browser surfaces unthemed: no `::selection`, no `caret-color` (the craft floor's "cheapest signal")
**Evidence.** `grep -n "selection\|caret\|scrollbar" console.css` returns **zero matches for selection or caret** — only scrollbar hits (`.pop` :466 `scrollbar-width: thin` but *no* `scrollbar-color`; `.pbody` :573 themed `var(--n-5) transparent`; `.slots`/`.cards`/`.suggest`/`.wbody` hide scrollbars entirely :547/:718/:742-743/:796). This while the console is deliberately copy-heavy: verbatim dissent quotes are a constitutional feature (DESIGN.md §4.4), coordinates and mono readouts everywhere. The skill's floor names this exact gap: selection, caret, scrollbars "ship with browser defaults that belong to no design system … the one models skip most reliably."
**Why it matters.** An operator selecting a TALON quote or a coordinate gets the browser's default blue highlight and default caret — the one moment the EOC Darkroom world visibly breaks.
**Fix (buildable).** Add to the token Tier 3: `--selection-bg` (e.g. from `--tint-talon-bg`) and set `::selection { background: var(--selection-bg); }` globally; `caret-color: var(--talon-ink)` on `.field input` and `.dissent textarea`; `scrollbar-color: var(--n-5) transparent` on `.pop` (matching `.pbody` :573). Daylight variants in the existing `:root[data-theme="daylight"]` block.

### P2-4 · Dock overflow affordance unpinned at 1440×900 (evidence stale, guard gap certain)
**Evidence.** `qa/final-polish.png` (crop 1300,680–1440,900) and `qa/final-rev.png` (crop 1330,680–1440,900) both show a fifth dock widget clipped to a ~36–87px sliver at the right edge with **no "+N widgets ▸" pill**, while `updateDockMore` (`commandConsole.ts:1089-1104`) counts any widget with `offsetLeft + offsetWidth > clientWidth + 1` and should have rendered one. Both captures are dated 2026-10-27 (`ls -la`), i.e. **they predate the 10-30 commits including the D3 dock-more work** — so current 1440 behavior is *unverified*; I did not launch the app. What is certain either way: the dock-overflow guard (DESIGN.md §7.3; `tools/e2e.mjs` V1) pins **1280** (pill must exist) and **1920** (no overflow) and leaves 1440 — where 5 widgets (316+380+344+336+316 + 4×8 gaps = 1724 > 1416 usable) always clip — unpinned. (At 1920 the `…OSED` text I first suspected in `qa/calm-plan.png` is a map zone label behind the dock, not a clipped widget — crop G disproved it; consistent with the 1920 no-overflow guard.)
**Fix (buildable).** Add a 1440×900 case to e2e phase D asserting `dockMore` visibility ⇔ a widget clips; also note `updateDockMore` only runs from `renderSlots` (`commandConsole.ts:1085`) — call it on `window.resize` too so a resized window can't keep a stale pill.

### P2-5 · Card meta row consumes the countdown's right padding at 1280
**Evidence.** `qa/e2e-break-1280.png` (crop 840,75–1240,135 at 3×): "10:00 left" ends flush against the card's right border — zero of the 16px `.card` padding (`console.css:605`) remains. The same card at 1920 (`qa/calm-plan.png`, crop 1470,70–1870,140) shows the full padding, so the meta row overflows only when narrow. `.card .meta` (`console.css:620-622`) sets no `min-width:0`/ellipsis on the caps label, so the auto-margined `.countdown` (`console.css:625`) is pushed to the border.
**Fix.** `.card .meta .caps { min-width: 0; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }` — the countdown keeps its padding; the long provenance label truncates instead.

### P2-6 · "Also waiting" accelerator hints collide with the map tool column (shared 68px anchor)
**Evidence.** `qa/final-polish.png` (crop 1120,420–1440,580): the collapsed "Also waiting" mini rows (`commandConsole.ts:784` — dot · title · `.countdown` · `.kbd` "Alt+N") run flush into the zoom tool group; the row's Alt+N kbd hint is not discernible in the render while the countdown "7:00 left" ends exactly at the tool column's left edge. Geometry cause: `.tools` and `.cards` **share** `right: calc(var(--gap) * 2 + var(--rail-w2))` = 68px (`console.css:452` and `:547`; `docs/anatomy/01-shell.html` header figure "CARDS-R = 2·GAP+RAIL = 68"), so the 40px tool column always occupies the card stack's right 40px band.
**Fix.** Displace the card stack by the tool width when both are visible — reuse the existing transform idiom (`console.css:553`, `translateX(calc(-1 * …))`) with `--tools-w` — or give `.mini .row` a `padding-right: calc(var(--s-3) + var(--tools-w))` so countdown and kbd never enter the tool band.

### P2-7 · Documented CONFLICT: concentric inner radius (resolve the comments, keep the value)
**Evidence.** `docs/anatomy/04-cards.html:145`: "† CONFLICT: TOKEN COMMENT SAYS R_inner = MAX(2, R1−PAD) → COA WOULD BE 2; SOURCE APPLIES 4 (R-XS). THE APPLIED VALUE GOVERNS." The CSS comments contradict their own formula: `--r-xs` sits under "/* radius (concentric: r_inner = max(2px, r_outer - padding)) */" (`console.css:276-277`), yet `.menu-item` (:470), `.coa` (:654) and `.dissent` (:673) all comment "concentric: 10px card/pop − 12px padding → 4px" — arithmetic the stated formula does not produce (`max(2, 10−12) = 2`).
**Fix.** Keep the applied 4px (the anatomy declares it governs); correct the three CSS comments and the token-block formula to the rule that actually governs — e.g. `r_inner = max(4px, r_outer − padding)` when padding ≥ r_outer — and mark the anatomy CONFLICT resolved in the next Rev.

### P2-8 · Unicode glyphs inside an otherwise drawn-icon system
**Evidence.** `commandConsole.ts:656` (`✓ … acknowledged`), `:687` (`⚠ Fragile if:`), `:1102` (`▸` in the dock-more label), `:1440` (`⟡ drone`, `✓ TAK synced`) are literal text glyphs, while the console owns an authored SVG system (`svg.ic`, one stroke/weight, `console.css:360-362`) and an `ic()` helper — the *adjacent* gate-check line already uses `ic('check','xs')` (TS:687), so the two systems coexist in one block. In the current capture the pill's `▸` renders as a faint dot-like mark (crop 990,565–1280,800), consistent with a fallback glyph; **I could not verify Geist Mono's coverage of U+25B8** (no font inspection run) — flagged for verification, not asserted.
**Fix.** Route the four markers through `ic()` (`check`, `alert-triangle`, `chevron-right`, drone) so stroke and weight match `svg.ic`; keep `✓` only where it is a prose sentence character, not a UI affordance.

### P2-9 · Sub-floor type: `.dchip .kbd` at 9px
**Evidence.** `console.css:1019` `.dchip .kbd { font-size: 9px; }` vs the console's own contract (DESIGN.md §2): "data-ink floor **10.5px** (`--fs-badge`, `--fs-chart`, `--fs-harness`)". No other sub-10.5px size exists in the file (full read).
**Fix.** `font-size: var(--fs-badge)` — or document the exception in DESIGN.md §2.

### P2-10 · "Zero-raw-hex" enforcement claim has drifted from source
**Evidence.** DESIGN.md §1: "no raw `#hex` or `rgba()` literal may appear in `console.css` outside the two token blocks (`:root` and `:root[data-theme='daylight']`) … Scanned clean as of 2026-10-28." The daylight token block closes at `console.css:1124`; the eight component-adjustment rules that follow (`:root[data-theme="daylight"] .glass` :1127, `.track .line` :1131, `.track .future` :1132, `.rail .rbtn .pips i`/`.budget .pips i` :1135, `.bar` :1136, `.conf/.dots/.steps i` :1137, `.switch` :1138-1139) contain raw `rgba(17,20,28,…)` / `rgba(255,255,255,…)` literals **outside** the token block. (The 10-28 scan predates these lines' current shape.)
**Fix.** Either promote those literals to named Tier-3 tokens defined inside the daylight block (e.g. `--track-line`, `--switch-knob`), or amend DESIGN.md §1 to name the daylight component-adjustment section as a third sanctioned location — one or the other; a contract that doesn't match its source stops being enforceable.

## (d) What the lens would genuinely praise

1. **The token system is load-bearing, not decorative.** Three tiers with an alias layer, a documented OKLCH deviation whose *reason* is real (the WebGL bridge shares the same literals so "cards and map can never disagree", DESIGN.md §1; `console.css:17-23`), and a zero-raw-hex contract (whose drift P2-10 is itself worth fixing *because* the contract exists).
2. **A real motion grammar, not scattered effects.** One curve (`--ease-out-expo`, `console.css:295`), a dual press idiom kept distinct for wide vs compact controls (:370-375, :630-633, primary travels 2px :379), entrance/exit asymmetry stated where it lives (`.tip` enter 120ms / exit 80ms, :555-556), compositor-only bar fills (:840-845), and a `prefers-reduced-motion` block that keeps state legible instead of going dark (:328-342) plus `prefers-reduced-transparency` (:343-345). This is the skill's "one authored moment" done as a system.
3. **Copy that names problem *and* recovery.** "If it lapses: Nothing is sent. I escalate to the Regional Duty Supervisor and keep the plan current." (TS:687, rendered in `qa/e2e-break-1280.png`); typed approvals are refused with a felt shake (`console.css:878-879`; DESIGN.md §4.5); controls name their action ("Authorize P-1", "Reject plan", "Hold at initial attack").
4. **Red discipline enforced three ways** — tokens (`.batt.low → --needs` `console.css:834`, pips amber :527/:565, mic violet :517-519), CI guards (DESIGN.md §7.1), and documentation (§5) — so a life-safety color stays meaningful.
5. **Provenance made visible at the pixel level**: MEA badges on wind/RH/temp/fuel in all four screenshots, the `.prov` ladder (`console.css:408-411`), and honestly-labeled trends ("session-observed sparkline (MEA)", :822-823) — the skill's "label illustrative values honestly" exceeded with a measured/modeled/authored taxonomy.
6. **AA floors held everywhere it matters**: `:focus-visible` ring + halo (:355, re-themed for daylight :1079), placeholder at `--text-4` 5.2:1 (:717; DESIGN.md §2), tabular numerals on every timestamp and readout (:356, :438, :625, :724, :832).
7. **The anatomy drawing set as living documentation** — dimensions, anchors, and *self-flagged CONFLICTs* (`04-cards.html:145`) rather than a glossy spec. The lens values evidence over intention; this repo documents its own deviations.
